# Progressive layer: charting baseline

Date: 2026-09-18. This document records the decisions settled while charting the second Wayfinder map. Each row names the principle that decided it, when one did. Principles live in `~/Developer/personal/dotfiles/principles/`. Tickets on the map refine these rows; they do not reopen them.

## Destination

A specification for the progressive layer of Effect Frame, plus seven specified example applications that prove it. The layer adds queries, a router, rendering modes, readiness, and a client-visible command lifecycle to the actor core. When the map closes, a build map can start with nothing left to decide.

| Route lifecycle         | Foldkit's Transition: data resolves on entering, is kept on stayed, is released on exited.                                                                                                                                                                                                                                       | Owner                                                    |
| Query staleness         | A query declares the actor contracts it depends on. A commit to one marks it stale and refreshes active instances in the command reply (single flight). | Query authorization     | The root host requires a policy table (`Policies`). No default table and no default rule exist. | Readiness               | Query state is a tagged union (loading, ready with stale flag, failed). `View.ready(query)` returns a synchronous-looking source and requires a readiness scope in context. `View.loading` and `View.errored` provide those scopes. Pending is derived from registered sources, never caught. The `Await` tag matches the union. | make-impossible-states-unrepresentable, derive-dont-sync |
| Refetch                 | Hold stale content; set the stale flag. The fallback shows only on first load.                                                                                                                                                                                                                                                   | experience-first                                         |
| Optimistic UI           | Automatic for transparent actors: `send` applies the message locally and marks the revision provisional; the receipt confirms or rolls back. Dependent queries show stale until the refresh lands. Explicit override remains for queries the dependency graph cannot know.                                                       | derive-dont-sync                                         |
| Server-driven wire      | Undecided. Two candidates get prototyped: markup morph per revision, and streamed host operations over the changes stream.                                                                                                                                                                                                       | exhaust-the-design-space                                 |
| Plain-form commands     | The server renders a hidden command id into every form. A double post hits the receipt.                                                                                                                                                                                                                                          | make-operations-idempotent                               |
| Prerender               | A route with finite param inputs rendered by the SSR pipeline at build. The client resumes from the rendered revision; queries revalidate.                                                                                                                                                                                       | derive-dont-sync                                         |
| Streaming SSR           | In scope. The shell streams first; readiness scopes hold open; pending queries serialize and resolve in the client.                                                                                                                                                                                                              | Owner                                                    |
| Server/client boundary  | File convention enforced by a build rule. No wrapper. A server module is named `*.server.ts(x)`; `bun run boundary` fails the gate when a browser entry reaches one. See `docs/design/boundary.md`.                                                                                                                              | encode-lessons-in-structure, composition-over-flags      |
| Command acknowledgement | A command is admitted before it is applied. The client sees the admitted signal separately from the applied revision.                                                                                                                                                                                                            | acknowledge-before-processing                            |

Each proves something no other proves.                                                                                                                                                                                        | experience-first                                         |

## Reference findings

The research that informed charting:

- SvelteKit remote functions: query, form, command, prerender; single-flight mutations; the authorization complaint in issue 17090.
- Foldkit: 35 example apps; Transition; commands that declare their messages; hydration through Flags; pain points in Submodel wiring and cold-load duplication.
- Solid 2.0: async memos; `NotReadyError` to a boundary; `isPending` and `latest`; `refresh` versus `affects`; stale content held on refetch; streaming SSR as default; `@solidjs/signals` rc.8 is what this repository already uses.
- React Server Components: module boundary by directive, Flight wire format, server functions with `permalink` for progressive enhancement.
