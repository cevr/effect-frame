# Effect Frame: acceptance matrix

Date: 2026-09-18. This table lists the claims Effect Frame makes about its destination, and the test that proves each one today. It is filled from the tests that exist in this repository right now. A claim with no test is Open, and the row says what is missing.

Read "Proven" as: a test in `bun run gate` fails if the claim stops being true. Read "Proven in-memory only" as: the claim holds over an in-process store or transport, and no test drives the real durable host. Read "Open" as: no automated proof exists yet.

## What "not in the gate" means

`packages/host-celld/scripts/crash-harness.ts` and `scripts/contract-proof.ts` need the celld 0.5.0 binary and take about a minute together. They run with `bun run proof:celld` and `bun run proof:contract` in the `@effect-frame/host-celld` package. Both passed on 2026-09-18 against `main` at `ed076c6`: 10 of 10 and 12 of 12 checks. CI does not run it. Its rows are proven against the real host, but a regression does not turn `bun run gate` red.

## The gaps, in order of risk

1. **Wake after a crash mid-task.** `contract-proof.ts` row g wakes the restarted object with one `snapshot` request, which is what a reconnecting client sends first. An object whose machine is mid-task with no pending command and no client stays dormant until a request or an alarm arrives; a heartbeat alarm for that case is not implemented.
2. **Placement as a declaration.** The example reads `NOTES_UPSTREAM` and swaps one layer. Nothing tests that swap. A test that starts the example against a celld host would close both this row and the one above.
3. ~~**Build enforcement of the import boundary.**~~ Closed by [#24](https://github.com/cevr/effect-frame/issues/24). `bun run boundary` fails the gate when a browser entry reaches a `*.server.*` module. See `docs/design/boundary.md`.
